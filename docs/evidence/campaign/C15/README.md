# C15 — CI credential boundary

Actual disposable Cloudflare execution `manual-cca4c60c18c68f6104e1c0f85c427112633844c473bff283b9f12c4054f58be6` passed at `b4e3fe7f7d3e76931b0f7a9dbdabc248c10cb402`. The repository command checked its environment, readable `/proc/*/environ` entries and the retained checkout's Git configuration. It emitted only `NO_PRIVILEGED_CREDENTIALS`. It never printed credential values. Both normalized status and authorized capture are saved here.

The approved JavaScript export now strictly rejects unknown fields, including arbitrary environments, credential toggles and secrets on steps/jobs. Runner calls explicitly disable Cloudflare and source-control credential injection. A push reads the approved definition from R2; it does not evaluate a pushed action file in the privileged Worker. Definitions require canonical administrator grants; writers can request runs but cannot approve configuration. Unknown namespaces/repositories are denied by the Worker allowlist.

Typed secret references expose binding names and purposes, never values. Existing Cloudflare/R2 values remain encrypted Worker secrets, and the dedicated control key is a private operator file. Generic repository CI has no organization/application secret injection or privileged deployment capability. A future deployment adapter must maintain a separate trusted boundary rather than passing a deployment token into repository commands.

Known Worker credential values, URI/base64/hex variants and captured trailing prefixes are redacted from provider captures/diagnostics. Approval rejects known privileged values before any definition source is written to Trestle. This cannot identify arbitrary unknown third-party secrets deliberately placed in source. Tests cover this rejection order, administrator access, strict schemas and encoded redaction; seven Worker protocol tests and Actions/app race suites pass.

Limits: sandbox commands have network access; isolation is not a claim of denied egress. The SDK uses a short-lived repo-scoped read token for checkout, outside the command environment. Capture redaction is defense in depth, not permission to inject secrets. Owner-approved JavaScript currently has time/stack/source limits without a hard Goja heap limit; operational hardening must address that separately before claiming tenant-safe configuration execution. Standard Workers Builds/deployment integration remains unconfigured.
