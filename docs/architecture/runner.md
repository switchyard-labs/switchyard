# Agent runner boundary

Switchyard's default runner is a trusted Go text adapter. `agent.Runner` accepts a context, typed repository/file task and attributed execution. It preserves exact text concatenation, including empty and Unicode content. It does not execute repository code. Git publication remains a separate control-plane effect.

`CLIRunner` is an explicit adapter protocol: JSON task on stdin, JSON `{ "files": { "path": "content" } }` on stdout, diagnostics on stderr. The configured executable is an absolute server-side path. Browser input cannot choose a binary or shell command. It runs under bubblewrap and prlimit; missing tools or namespace permission fail closed. No production provider is automatically enabled by this checkpoint.

The sandbox exposes read-only system binaries/libraries, a private workspace, isolated home/tmp, and a scoped credential file when explicitly resolved. Host home, environment and configuration are absent. Networking is denied by default and requires explicit adapter configuration. The service must run as a dedicated non-root user before enabling real subprocess Agents. PID/user/mount namespaces, process-group cancellation, parent-death cleanup, wall-clock deadline, address-space/CPU/file/output limits and an in-namespace process limit constrain execution. These process limits are not an aggregate cgroup memory budget; deployment sizing and concurrency limits still matter.

Default limits are two minutes, two GiB address space, 120 CPU seconds, 256 processes, 128 file descriptors, 16 MiB file size and one MiB combined captured output. Output overflow fails result parsing. Paths and total returned content are validated. Exact scoped credentials are redacted from captured output and rejected in returned file content. This does not promise to detect arbitrary secret encodings; untrusted code must never receive trusted secrets.

Started/output/finished events identify stdout/stderr and timestamps. Captured output events are delivered after the process exits; this adapter is not the Cloudflare Actions streaming log transport. Execution metadata records status, duration, exit code, CPU time, truncation and sandbox use. Credential files are deleted on success, start failure, cancellation and timeout. HTTP draft proposals use request cancellation; workflows propagate their execution context. Trusted Git transport helpers have deadlines, environment/config isolation and bounded output.

Tests use real disposable sandbox adapter scripts, not a provider credential: host-file/environment isolation, JSON protocol, separate diagnostics, timeout, background-descendant cleanup, output limits, scoped-secret redaction/deletion and deterministic text parity. Live coding-provider compatibility remains to be certified against a selected provider/CLI.
