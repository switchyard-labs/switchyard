# Checkpoint 3 handover

- **Checkpoint:** CP3 — Safe Git/ref mutation substrate
- **Status:** PASS
- **Commit:** (see CP3 commit below)

## Objective
Implement and certify the safe mutation primitive `UpdateRef(repo, ref,
expected_sha, new_sha, provenance)` with per-ref CAS semantics, pressure-tested
against stale writers, while preserving ordinary human Git behaviour.

## What changed
- `internal/refs` — the ref-mutation service:
  - `Update(repo, branch, expected, changes, message, provenance)` builds a
    commit in a disposable scratch clone and CAS-updates the ref via a
    **non-force git push** (git's expected-old enforcement, validated in E1).
  - Per-ref in-process serialization (per-ref lock); no repository-wide lock.
  - Stale detection: expected mismatch (pre-push) or rejected push → `STALE`
    with the current SHA for reconciliation.
  - Repo-scoped git tokens minted via Artifacts `POST /tokens` and cached
    (write scope, 15 min TTL).
  - Provenance recorded in a Trestle `ref_updates` collection.
- API: `GET /api/repos/{name}/refs` (ls-remote read path) and
  `POST /api/refs/update` (CAS mutation endpoint).

## Architecture decisions
- Git protocol operations use **repo-scoped tokens** (`art_v2_…`), not the
  account REST token (`cfoat_…`) — a real finding from this checkpoint.
- The substrate is a primitive/service, not a user-facing queue; the
  Integration Queue (higher-level canonical scheduling) builds on it later.

## Tests / evidence
- `experiments/cp3/cp3_gate.sh` + live output: three writers to `main` —
  correct-CAS → `ok`; stale-expected → `STALE`; updated-expected → `ok`.
  Final tree contains only the two successful writers' files; Trestle
  `ref_updates` records both successful mutations with provenance.

## Failures / rough edges
- `git clone -c http.extraHeader=…` **persists the header into the new repo
  config**, producing duplicate Authorization headers and an Artifacts HTTP 400
  on later ops. Fixed by unsetting `http.extraheader` after the scratch clone.
  (Significant git footgun; documented.)
- Minted tokens return HTTP 201 (client initially only accepted 200).
- Ref mutation on a non-existent branch is not yet supported (CP4 adds
  branch-from-base).

## Security review
- Repo tokens are short-TTL (15 min) and repo-scoped; account token never used
  for git. Non-force push only. Provenance records no secrets.

## Performance / concurrency observations
- Per-ref isolation confirmed; no global lock. Scratch clone+commit+push per
  mutation (~seconds) — fine for this scale; the validation cache and
  merge-train mechanics are later CP9 work.

## Impact on later checkpoints
- CP4 (deterministic slice) uses the refs substrate for attempt branches and
  canonical integration. CP9 (Integration Queue) adds ordering/preview/policy on
  top of this primitive.
