# Checkpoint 5 handover

- **Checkpoint:** CP5 — Events, provenance, reconciliation, realtime
- **Status:** PASS
- **Commit:** (see CP5 commit below)

## Objective
Turn CP0 event proof + CP2–CP4 application state into a real production-shaped
event/reconciliation/provenance/realtime layer. Gate: an external Git/event
mutation propagates into Switchyard state and into the realtime UI without
manual refresh.

## What changed
- **Reconciliation** (`internal/app/reconcile.go`): a periodic poller (default
  15s) that diffs Artifacts Git truth (refs via `git ls-remote`) against Trestle
  `ref_obs` observations. On ref change (external push, branch create/move) it
  writes a durable normalized `git.ref_changed` event (idempotent) and
  broadcasts it. Append-only `ref_obs` history; restart-safe (no re-emission
  for unchanged state).
- **Realtime** (`internal/app/stream.go` + `handleEventStream`): control-plane
  SSE hub. The control plane is the coordination truth, so it is also the
  realtime source for browsers (the documented equivalent of the Worker/DO
  bridge; no edge → private-Trestle assumption). Authenticated SSE endpoint
  with ready/heartbeat frames.
- **Provenance** (`internal/app/provenance.go`): `GET /api/work/{id}/provenance`
  assembles the chain work → attempts → runs → PRs → ref_updates → events
  (derived view, structured facts, no raw model text).
- Browser UI: dashboard "Live activity" panel wired to `EventSource`
  (`/api/events/stream`); events render without refresh.
- Collections: `ref_obs`.

## Gate evidence
`experiments/cp5/cp5_gate.sh` (live): seeded repo; SSE client connected; initial
reconciliation recorded baseline; an **external human `git push`** was detected
by reconciliation; SSE received `git.ref_changed` (`after=04a3ace`, `old=
79fb72b`) — browser-update path proven without manual refresh. Control-plane
restart did not duplicate events. Duplicate ingest returned `replayed: true`.
Provenance chain for a full Work→Attempt→run→PR→integrate run assembled
correctly (including the merge `ref_update` with `provenance: merge:user:alice
pr:...`).

## Findings / rough edges
- First reconciliation pass emits a baseline `git.ref_changed` per repo/branch
  (`old=""`) — expected noise; subsequent passes only emit on real change.
- SSE drops events for slow subscribers (bounded channel) — reconnection +
  reconciliation provide the durable safety net.
- Event delivery is poll-driven (~15s); fine for a coordination dashboard.

## Security review
- SSE endpoint is session-authenticated; events contain repo/branch/sha facts
  only (no secrets). Reconciliation uses repo-scoped git tokens.

## Impact on later checkpoints
- CP9 (Integration Queue) can rely on reconciliation for canonical-freshness
  detection and stale invalidation.
- CP13 dogfooding can observe its own pushes in realtime.

## Addendum (corrective) — CP5 reclassified CONDITIONAL PASS

**Original classification was over-broad.** The CP5 gate demonstrated:

```
Artifacts
  ↓
periodic git ls-remote reconciliation (≈15 s)
  ↓
normalized git.ref_changed → Trestle
  ↓
control-plane SSE
  ↓
browser
```

That is the **reconciliation safety net**: external Git movement detection,
idempotent normalized state, restart safety, browser realtime without refresh,
provenance assembly. All genuinely proven.

What it is **not** is the production-shaped **event bridge** established in
CP0:

```
Artifacts push → cf.artifacts.repo.pushed → Cloudflare Queue →
Switchyard control-plane consumer → idempotent ingest → Trestle → SSE → browser
```

### Corrective architecture (fast path + safety net)

- **Fast path:** real `cf.artifacts.repo.pushed` events land in a Cloudflare
  Queue; the Switchyard control plane pulls batches (pull-based consumer —
  self-hosted control plane is not reachable from the Cloudflare edge, per CP0
  finding 7) and ingests each through `observeTransition`.
- **Safety net:** the reconciliation poller is retained as-is (periodic ref
  comparison, repair of missed/stale/delayed events, external direct-push
  detection).
- **Idempotency identity:** `(repo, ref, before, after)` — deliberately free
  of delivery metadata (queue message id, `seen_at`). Both paths converge on
  one durable `git.ref_changed` domain event and one SSE broadcast, verified
  by the live gate.
- **Invariant:** *events accelerate convergence; reconciliation guarantees
  eventual convergence.*

## Addendum 2 (corrective follow-up) — CP5 upgraded to PASS

**Status change:** CP5 is now **PASS** via this follow-up commit. The real
event fast path is wired into the product and gated:

```
Artifacts push (real) → cf.artifacts.repo.pushed → Cloudflare Queue →
Switchyard control-plane consumer (pull-based, per CP0) →
observeTransition → Trestle domain event → control-plane SSE → browser
```

### Implementation (follow-up commit)
- `internal/app/observe.go` — the single normalized ingest path
  `observeTransition(repo, branch, before, after, source)`: append-only
  `ref_obs` audit observation + one durable `git.ref_changed` domain event
  (identity `(repo, ref, before, after)`), SSE broadcast only on first
  creation.
- `internal/app/queue.go` — Cloudflare Queues pull consumer (REST
  `messages/pull` + `messages/ack`), ingest via `observeTransition`, ack on
  success, retry on failure (at-least-once).
- `internal/app/reconcile.go` — reconciliation now feeds the same
  `observeTransition`; first observation of a branch records a baseline only
  (no fabricated `before=""` transition, so queue and reconciliation agree on
  the transition identity).
- `cmd/switchyard/main.go` — `SWITCHYARD_QUEUE_ID`,
  `SWITCHYARD_QUEUE_PULL_INTERVAL` (fast path optional; reconciliation is the
  safety net when no queue is configured).
- Idempotency semantics: Trestle returns `replayed=true` only for
  byte-identical content; the same transition identity with different path
  metadata (seen_at/source) yields `409 idempotency_conflict`. Switchyard
  treats that 409 as **convergence** (the domain fact already exists once) and
  acks — no retry churn, no duplicate broadcast.

### Gate evidence (`experiments/cp5/event/cp5_event_gate.sh`, live, 6/6)
- **Fast path:** with reconciliation disabled, a real push + injected
  real-schema event → exactly one domain fact `source=queue`, one SSE frame.
- **Duplicate queue delivery:** two identical events → one domain fact.
- **Reconciliation first:** queue disabled, push → reconciliation ingests one
  fact (`source=reconciliation`); re-enabling the queue and delivering the late
  event dedups (still one).
- **Control plane unavailable:** push while down; on restart the queued event +
  reconciliation converge to one fact; queue drained (backlog 0, acks landing).
- Domain facts for the gate repo: exactly 4 transitions, correct source per
  phase, zero duplicates.

### Upstream condition (honest, non-Switchyard)
Cloudflare event-subscription → Queue delivery for `cf.artifacts.repo.pushed`
is currently not flowing account-wide (CP0 delivered; fresh repos +
subscriptions deliver nothing). The Switchyard fast-path implementation is
complete and gated with real-schema envelopes and real observed SHAs;
reconciliation is the live correctness path meanwhile. Re-verify the live
Cloudflare delivery leg when the upstream delivery resumes; no Switchyard code
change is expected.

## Addendum 3 (post-cp13 review) — CP5 reclassified CONDITIONAL PASS

**Final reviewed status: CONDITIONAL PASS.** The corrective fast-path work is
kept: the dual-path architecture (queue fast path + reconciliation safety net)
and the shared transition identity `(repo, ref, before, after)` are strong
results. But the final CP5 event gate did NOT re-prove the complete production
source leg:

```
real Artifacts push → Cloudflare Artifacts event subscription → Queue
```

because Cloudflare's event-subscription delivery stopped flowing account-wide
(identical config delivered in CP0; recreated fresh for new repos; nothing
delivered). The gate instead injected a real-schema `cf.artifacts.repo.pushed`
envelope into the Queue and proved the consumer, queue pull/ack, normalization,
idempotency, duplicate delivery, both orderings, offline recovery, and SSE.

Condition: re-certify the live `push → auto-delivered event → Queue →
Switchyard → Trestle → SSE` leg when the upstream delivery resumes, then
upgrade CP5 to PASS in a follow-up commit. Reconciliation guarantees eventual
convergence meanwhile; this is an upstream observation, not a Switchyard
architecture failure.
