# Checkpoint 5 handover

- **Checkpoint:** CP5 — Events, provenance, reconciliation, realtime
- **Status:** PASS
- **Commit:** (see CP5 commit below)

## Objective
Turn CP0 event proof + CP2–CP4 application state into a real production-shaped
event/reconciliation/provenance/realtime layer. Gate: an external Git/event
mutation propagates into Switchyard state and into the realtime UI without
manual refresh.

## What changed
- **Reconciliation** (`internal/app/reconcile.go`): a periodic poller (default
  15s) that diffs Artifacts Git truth (refs via `git ls-remote`) against Trestle
  `ref_obs` observations. On ref change (external push, branch create/move) it
  writes a durable normalized `git.ref_changed` event (idempotent) and
  broadcasts it. Append-only `ref_obs` history; restart-safe (no re-emission
  for unchanged state).
- **Realtime** (`internal/app/stream.go` + `handleEventStream`): control-plane
  SSE hub. The control plane is the coordination truth, so it is also the
  realtime source for browsers (the documented equivalent of the Worker/DO
  bridge; no edge → private-Trestle assumption). Authenticated SSE endpoint
  with ready/heartbeat frames.
- **Provenance** (`internal/app/provenance.go`): `GET /api/work/{id}/provenance`
  assembles the chain work → attempts → runs → PRs → ref_updates → events
  (derived view, structured facts, no raw model text).
- Browser UI: dashboard "Live activity" panel wired to `EventSource`
  (`/api/events/stream`); events render without refresh.
- Collections: `ref_obs`.

## Gate evidence
`experiments/cp5/cp5_gate.sh` (live): seeded repo; SSE client connected; initial
reconciliation recorded baseline; an **external human `git push`** was detected
by reconciliation; SSE received `git.ref_changed` (`after=04a3ace`, `old=
79fb72b`) — browser-update path proven without manual refresh. Control-plane
restart did not duplicate events. Duplicate ingest returned `replayed: true`.
Provenance chain for a full Work→Attempt→run→PR→integrate run assembled
correctly (including the merge `ref_update` with `provenance: merge:user:alice
pr:...`).

## Findings / rough edges
- First reconciliation pass emits a baseline `git.ref_changed` per repo/branch
  (`old=""`) — expected noise; subsequent passes only emit on real change.
- SSE drops events for slow subscribers (bounded channel) — reconnection +
  reconciliation provide the durable safety net.
- Event delivery is poll-driven (~15s); fine for a coordination dashboard.

## Security review
- SSE endpoint is session-authenticated; events contain repo/branch/sha facts
  only (no secrets). Reconciliation uses repo-scoped git tokens.

## Impact on later checkpoints
- CP9 (Integration Queue) can rely on reconciliation for canonical-freshness
  detection and stale invalidation.
- CP13 dogfooding can observe its own pushes in realtime.
