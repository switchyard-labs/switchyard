# Checkpoint 2 handover

- **Checkpoint:** CP2 — Control-plane foundation
- **Status:** PASS
- **Commit:** (see CP2 commit below)

## Objective
Smallest real Switchyard application/control-plane foundation: auth/session,
users, repository registration + metadata, repository browser, normalized
Artifacts event ingestion (idempotent), and an initial Work model.

## What changed
- New Go control plane (`cmd/switchyard`, `internal/`): a single binary serving
  the Nift-built web app and the JSON API.
  - `internal/trestle` — minimal Trestle client (admin session + CSRF, ensure
    collection, idempotent record create, list records).
  - `internal/artifacts` — minimal Artifacts REST client (list/get/log/tree/
    raw file) + token refresh via the approved helper (`/opt/cp0/switchyard/
    token.sh`, the cf OAuth token).
  - `internal/app` — HTTP server + auth (register/login/session cookie),
    repos (list/get/tree/content), work (list/create/get), events (idempotent
    ingest + list), static serving.
- Nift web application: dark-first shell, site-wide `<title>Switchyard</title>`,
  favicon (`public/assets/images/favicon.webp`), hamburger + full-screen mobile
  menu (Escape/focus-trapped), app.js island hydrating the pages (dashboard,
  sign-in, work, repo browser).
- Collections provisioned on the single-node Switchyard Trestle (port 7350):
  `users`, `sessions`, `repos`, `work`, `events`.

## Architecture decisions (this checkpoint)
- Trestle is the coordination truth (users/sessions/work/events/repos metadata);
  Artifacts is the Git truth (repos, trees, files) — authority split held.
- Session cookie (`switchyard_session`, HttpOnly, SameSite=Lax) over a Trestle
  `sessions` collection; passwords bcrypt-hashed in `users`.
- Normalized event ingest is idempotent at the Trestle boundary via
  `Idempotency-Key` (revalidated live: duplicate ingest returned `replayed:
  true`, one record).
- Repo browser reads Git truth directly through Artifacts REST (tree walk from
  branch tip; raw file reads). No separate file store.
- Trestle filter syntax uses single `=` (not `==`) — corrected during the gate.

## Tests / evidence
- `experiments/cp2/cp2_gate.sh` + live output: register/login, `me`,
  repo list (12-13 real repos), repo metadata, tree (`README.md`,
  `src/main.go`), file content bytes, work create/list/get, idempotent event
  ingest, events list.
- Web UI verified: `Switchyard` title on every page, favicon 200 image/webp,
  app.js/hamburger present.

## Failures / rough edges
- Trestle list responses nest values under `.items[].values` (client fixed).
- Trestle filter uses `=` not `==` (fixed).
- `work` collection initially missing its `id` field → 422 (fixed by
  provisioning `id` and recreating the dev collection).
- Control-plane binary cannot be overwritten while running (stop→replace→start).

## Security review
- Passwords bcrypt-hashed; sessions HttpOnly + SameSite=Lax + expiry.
- No secrets in the control-plane logs or Git; Artifacts token obtained via the
  approved helper, never embedded.
- Auth gate on all API endpoints (repos/work/events).

## Performance / concurrency observations
- Per-request Artifacts REST reads with a 2-minute token cache; fine at this
  scale. No global locks introduced.

## Deferred / upstream work
- No upstream changes. Full event bridge (Cloudflare Worker → control plane)
  and provenance graph are CP5. Reconciliation job (repo truth vs registry) is
  partially present via auto-registration on first browse; full scheduled
  reconciliation lands in CP5.

## Impact on later checkpoints
- CP3 (ref substrate) builds directly on the Artifacts client + git helpers.
- CP4 (deterministic slice) uses Work + repos + Trestle coordination.
- CP5 (events/provenance/realtime) extends the ingest surface and adds the
  Worker bridge.
- CP10 (editor) reuses the same static/app shell and auth.
