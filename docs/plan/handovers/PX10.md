# PX10 — User profile data model + avatar pipeline
- **Status:** CONDITIONAL PASS (backend implementation complete; multipart/live Trestle gate deferred to normal environment).
- Added `user_profiles` separate from auth secrets: bio, location, website, social links, avatar metadata.
- Profile update endpoint preserves authentication/account separation.
- Avatar upload/change/remove supports PNG/JPEG/WebP/GIF, hard 2 MiB limit, server-side MIME sniffing, private data-dir storage and generated near-black/amber fallback SVG.
- Avatar bytes are not stored in Git or Trestle records; the path is abstracted behind `/api/avatars/user/{username}` for later object/KMS-hosted deployment.
- Large-avatar profile presentation is delivered in PX11; nav/list consumption can use the same URL immediately.

**Security:** no remote-avatar URL/SSRF path; untrusted SVG uploads are rejected; avatar files are created 0600 under the Switchyard data directory.
