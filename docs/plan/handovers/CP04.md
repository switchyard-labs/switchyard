# Checkpoint 4 handover

- **Checkpoint:** CP4 — Deterministic end-to-end vertical slice
- **Status:** PASS (the early reality check)
- **Commit:** (see CP4 commit below)

## Objective
Prove the full Switchyard loop with **no AI model**: Work → Attempt → Strut
executor → deterministic repository edit → Git commit → Pull Request →
check/validation → Integration Queue → canonical integration, against real
Artifacts Git truth and real Trestle coordination truth.

## What changed
- `internal/refs`: branch-from-default creation (Update on a missing branch),
  `MergeBranch` (canonical integration primitive: clone target, fetch source,
  merge --no-ff, non-force CAS push, provenance).
- `workers/deterministic.p` — a bounded **Strut** worker: reads a task JSON,
  reads current file content, appends a deterministic line, writes the new
  content, reports. Compiled on the Linode (`deterministic-worker`).
- `internal/app/attempts.go` + `prs.go`: Work → Attempt (isolated branch) →
  run (Strut worker + refs substrate) → open PR → deterministic check →
  integrate (MergeBranch) → mark PR integrated.
- `internal/trestle`: `FindRecord` + `PatchRecord` (If-Match optimistic update)
  so PR status is updated on integration.
- Collections: `attempts`, `runs`, `prs`, `pr_checks`.

## Gate evidence
`experiments/cp4/cp4_gate.sh` (live): created Work, created Attempt on an
isolated branch, ran the Strut worker (deterministic append, committed, pushed),
opened a PR, deterministic check passed, integrated via the queue (merge into
`main`). Canonical `main` tree now contains `ATTEMPT.md` with the deterministic
change; `ref_updates` records the full chain (branch create, run commit, merge
with `provenance: merge:user:alice pr:...`); PR status `integrated`, check
`pass`; `runs` recorded.

## Failures / rough edges
- `attempts` collection initially missing its `message` field (422) — fixed.
- Merge commit needed a git identity (`-c user.name/email`) — fixed.

## Security review
- Repo tokens short-TTL and repo-scoped; non-force pushes throughout; the
  merge path never uses force. Provenance records no secrets.

## Performance / concurrency observations
- Per-ref isolation holds across the slice (branch create, run commit, merge all
  independent ref operations). Merge-branch + CAS means a stale canonical base
  is rejected cleanly (retry semantics for the queue).

## Impact on later checkpoints
- Proves the control-plane/event/Git/ref semantics and the Strut executor
  integration — the substrate is real, not aspirational.
- CP5 (events/provenance/realtime), CP6 (agent execution replaces the
  deterministic worker), CP9 (full Integration Queue semantics) build directly
  on this slice.
