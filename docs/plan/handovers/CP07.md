# Checkpoint 7 handover

- **Checkpoint:** CP7 — Durable workflows
- **Status:** PASS (gate: `experiments/cp7/cp7_gate.sh`, live 9/9)

## What changed
- `internal/app/workflows.go` — durable workflow engine:
  - collections: `workflows` (JS definitions), `workflow_runs` (durable state,
    status/params/script/budget/steps/output/error/parent/depth),
    `wf_steps` (durable steps: run_id, step_key, op, args_hash, status, result,
    attempts).
  - API: create/list workflows, start run, list/get runs, cancel, approve,
    retry. Runner loop (`StartWorkflowRunner`, concurrent per-run with an
    in-flight guard) + `promoteWaitingParents` (child completion resumes the
    parent).
- `internal/app/workflow_exec.go` — the goja-based interpreter:
  - authoring model: JS `run(ctx)`; `ctx.agent/check/review/integrate/
    wait_approval/spawn/sleep/note/parallel` are Switchyard operations.
  - durability: every operation is a durable step keyed by `(run_id,
    step_key)` + args_hash; on replay the recorded result is returned instead
    of re-executing. The workflow script is re-run from the top each pass
    (Temporal-style replay); completed steps replay, in-flight steps
    re-execute (bounded retries), and completed external effects are never
    duplicated.
  - determinism: `Math.random`→const, `Date.now`→0, seeded `ctx.random(seed)`;
    step-key counter is deterministic per pass.
  - parking: `wait_approval` parks the run (waiting_approval) until the
    approval API resumes it; `spawn` creates a deterministic-id child and
    parks (waiting_child) until the child completes. Budget (step cap) and
    bounded recursion (max depth 4) enforced. Cancellation is cooperative
    (checked between steps and inside cancellable sleeps).

## Gate evidence (live, 9/9)
1. Basic durable run (agent→check→integrate) completes; exactly 1 execution.
2. **Executor death:** control plane killed during `sleep`; on restart the run
   resumed idempotently — agent step1 replayed (attempts=1), only step2+check
   executed (2 new steps), executions=2 (no duplicated external effects),
   sleep re-executed (attempts=2, in-flight at-least-once).
3. Spawn child + wait on approval: parent waits for child, parks on approval,
   resumes after approval, integrates.
4. Cancellation mid-sleep stops further steps (0 agent steps after cancel).
5. Parallel branches (agent + review) both durably recorded.
6. Recursive self-spawn is depth-bounded (fails at depth 4).

## Security notes
Workflows execute with the same role-scoped substrate as attempts (deterministic
adapter; no provider credential). The JS surface is constrained and
deterministic; no network/file access is exposed to workflow scripts. Child
runs inherit parent params but no additional authority.

## Performance notes
Steps are recorded with one Trestle create + one patch. Replay is cheap
(lookups). The single-node runner executes runs concurrently with an in-flight
guard; long sleeps are cancellable in 500 ms chunks.
