# Checkpoint 10 handover

- **Checkpoint:** CP10 — Browser editor + Agent panel
- **Status:** PASS (gate: `experiments/cp10/cp10_browser.mjs` driven against a
  real headless Chromium via Playwright; live 13/13)

## What changed
- `internal/app/editor.go` — editor backend:
  - `drafts` collection; POST/GET drafts (**upsert**: unique idempotency key
    per save; a deterministic draft id is patched on resave — the same Trestle
    409-idempotency_conflict semantics as CP5 apply, so drafts are upserted,
    not re-created).
  - `POST /api/drafts/{id}/commit` applies a draft to Git via the **shared ref
    substrate** (`refs.Update`, CAS-guarded) — Save is NOT Commit; only this
    endpoint changes the repository.
  - `POST /api/diff` — unified diff (git diff --no-index in a scratch dir) for
    the shared diff surface.
- `public/edit.html` + `public/assets/js/app-editor.js` + editor.css:
  - **CodeMirror 6** vendored as `cm6.bundle.js` (esbuild bundle of the 6.x
    packages: view/state/commands/language/theme-one-dark; built as a single
    IIFE global `CM6`).
  - CM6 editor with line numbers, history, highlight, oneDark.
  - Save draft button (durable, survives reload) vs Commit button (prompts for
    a message, applies via the shared substrate).
  - Diff panel (draft vs committed), findings list (file-scoped), hideable
    Agent panel (runs the implementer against an attempt and refreshes the
    committed content).
- `public/repo.html`/app.js: "Edit in editor" link per file; `refreshAuth`
  exposed as a global for the editor page.
- Bug fixes found by the browser gate: `.mobile-menu[hidden]` CSS override was
  covering every page (all clicks intercepted); draft-save 409 semantics;
  diff error handling in `runGitOut`; the agent run call was missing `POST`.

## Gate evidence (live, real Chromium, 13/13)
1. CM6 editor renders; title set.
2. Save shows "draft saved (not committed)" — the branch is NOT modified.
3. **Draft survives reload** (editor content == draft, != committed branch
   content, state shows saved) — Save != Commit honored.
4. Diff surface shows the draft vs committed unified diff.
5. **Commit applies via the shared substrate**; committed content on the
   branch; draft cleared after commit.
6. **Agent panel** runs the implementer against the attempt branch; the agent's
   edit lands in the editor and is committed to the attempt branch (ATTEMPT.md
   grows 1 → 6 lines across the loop).

## Security notes
Drafts are user-scoped and durable in Trestle; commits carry provenance
(`editor:<user>:<draft>`). CM6 is vendored (no runtime CDN); the editor talks
to the authenticated control-plane API only.

## Performance notes
CM6 bundle is ~670 KB (minified IIFE). Draft ops are single Trestle records.
The diff endpoint shells out to git in a scratch dir (same scratch-clone costs
flagged in CP9; acceptable here).

## Impact on later checkpoints
- CP11 Needs Attention maps blocked/conflict/waiting items into the UI.
- CP12 org policy can gate commits/integrations without touching the editor.
- CP13 dogfooding: the editor is a real surface for Switchyard-on-Switchyard.

## Addendum (post-cp13 review) — draft revision/CAS concurrency (6/6)

The editor backend now implements **optimistic concurrency with no
last-writer-wins**. A draft retains `id, repo, branch, path, base_sha,
content, revision, user, updated_at` (ephemeral/recoverable — not another VCS).

- `POST /api/drafts` accepts `expected_revision`; a save whose
  `expected_revision` != current revision is rejected with
  `409 draft_stale {expected_revision, current_revision}` — never silently
  overwriting newer content. Drafts also record `base_sha` (the branch head the
  client based the draft on).
- `POST /api/drafts/{id}/commit` compares `base_sha` to the current branch head
  and rejects with `409 stale_base {draft_base_sha, current_head, guidance}` on
  external branch movement (through the existing ref CAS substrate), so the
  user reconciles rather than losing the draft.
- Editor client tracks the current revision and base SHA and handles both stale
  cases by reloading the current draft/committed content.

### Draft concurrency gate (live, 6/6)
- **Race A (two sessions):** both load rev 1; S1 saves → rev 2; S2 (holding
  rev 1) save → `draft_stale`; S1's newer content preserved.
- **Race B (Agent vs human):** human saves rev 2 → 3; an Agent result based on
  rev 2 is rejected (`draft_stale`); the human edit is preserved.
- **Race C (external push):** draft based on A; branch pushed to B; commit →
  `stale_base`; the draft content remains recoverable.

### Agent panel mode classification (accurate)
The current Agent panel runs the implementer through the **formal Attempt
execution path** (workflow/attempt on the attempt branch) and then refreshes the
committed repository state — that is legitimate autonomous Work/Attempt
execution that produces commits. The **interactive draft-assistance** flow
(Agent result proposed onto the human's draft, human inspects the diff, human
chooses Commit — no automatic commit) is NOT yet implemented. That gap is
recorded for CP14/v1 (the draft CAS machinery above is the correct substrate for
it: an Agent result would arrive as a save with the human's revision, and a
stale result would be rejected exactly like Race B).
