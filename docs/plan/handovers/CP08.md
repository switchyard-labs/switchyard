# Checkpoint 8 handover

- **Checkpoint:** CP8 — Reviews/findings + conflict
- **Status:** PASS (gate: `experiments/cp8/cp8_gate.sh`, live 6/6)

## What changed
- `internal/app/reviews.go`:
  - structured `findings` collection (target, severity, message, file, status,
    resolved_at); machine-actionable, durable.
  - `handleReviewAttempt` — reviewer role: deterministic review (changed-file
    inventory + marker quality + size limits) recorded as findings and an
    execution record.
  - `handlePreview` — preview integration: `refs.PreviewMerge` tests whether the
    attempt merges cleanly into current base; on conflict records error
    findings and routes the attempt to `conflict`.
  - `handleResolveConflict` — conflict-resolver role: `refs.ResolveIntoSource`
    performs a real three-way merge (git merge-file) into the source branch;
    findings closed as resolved; attempt marked `resolved`; bounded single-pass
    repair loop.
  - `GET /api/findings`.
- `internal/refs/refs.go`:
  - `PreviewMerge` — clone target, fetch source, `git merge --no-commit --no-ff`
    (with identity config), enumerate `--diff-filter=U` files, abort. No remote
    ref is modified (preview only).
  - `ResolveIntoSource` — clone target, merge source, resolve each conflicted
    file via `git merge-file -p <ours> <base> <theirs>` (three-way); if it still
    conflicts, the source's version wins (deterministic bounded policy) with a
    recorded resolution; commit and push the resolution onto the SOURCE branch.
- `internal/app/gitutil.go` — scratch git helpers + durable execution-record
  helper.

## Gate evidence (live, 6/6)
1. Review produces structured findings (info/warning, open).
2. Two competing attempts (both editing shared.txt line3) produce two
   comparable open PRs.
3. Attempt A integrates first; attempt B's **preview integration detects the
   semantic/structural conflict** (shared.txt + ATTEMPT.md) without touching
   canonical, and records error findings.
4. **Conflict-resolver repair loop**: three-way merge resolves both files;
   attempt → `resolved`.
5. Re-preview after resolution is clean.
6. B integrates cleanly into canonical; the final shared.txt reflects the
   deterministic resolution policy (source-wins on the unresolvable line).

## Security notes
Conflict resolution and review run through the same role-scoped substrate
(reviewer / conflict-resolver); no provider credential involved. Preview
operates in a scratch clone and never mutates remote refs.

## Performance notes
Preview/resolve each do one scratch clone + fetch (seconds at this scale).
Changed-file review also uses a scratch diff. These are the same scratch
clone-per-operation costs flagged for CP9 measurement.

## Addendum (post-cp13 review) — terminology: textual vs semantic conflict

CP8 proves **textual/Git merge conflict** detection during preview integration
(overlapping edits to the same lines/files produced real Git conflicts) plus a
deterministic repair loop, re-preview, and successful integration. It is NOT
evidence of semantic-conflict detection. Accurate wording:

- the CP8 gate = "textual/Git merge conflict detected during preview
  integration";
- preview integration is the substrate on which semantic checks can later run;
- the semantic-conflict experiment is `experiments/cp8/semantic/`.

The architecture continues to distinguish textual Git conflict, structural
conflict, semantic conflict, intent conflict, and policy conflict; they are not
collapsed merely because they all block integration.

## Addendum 2 (post-cp13 review) — real semantic-conflict experiment (5/5)

The semantic-conflict claim is now proven by a dedicated experiment
(`experiments/cp8/semantic/`): **a Git merge that is textually clean but whose
combined tree violates an explicit contract becomes a semantic finding and
blocks the Integration Queue.**

Fixture: `api/version.json:version` must equal every consumer's
`requires_version` (`switchyard.contract.json` rules). Attempt A moves
api + consumer to 2 together (contract holds, integrates). Attempt B adds a
NEW consumer file `consumers/gamma.json` with `requires_version:3` — a
different file, so `git merge` of B into main is CLEAN. Deterministic
contract validation on the merged tree reports
`api/version.json:version (2) != consumers/gamma.json:requires_version (3)`:
a semantic error finding, the attempt is parked `semantic_conflict`, and the
Integration Queue blocks the item.

This proves the model:
`preview merged tree → deterministic contract validation → clean Git merge but
incompatible semantics → semantic finding → block Integration Queue`.
No LLM is involved; the contract engine is a bounded deterministic rule set
(`field_equals`) that can be extended. CP8's main gate remains textual/Git
conflict handling; semantic conflict is now separately evidenced.
