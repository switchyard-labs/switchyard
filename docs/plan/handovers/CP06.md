# Checkpoint 6 handover

- **Checkpoint:** CP6 — Real Agent execution + credentials
- **Status:** CONDITIONAL PASS
- **Condition (bounded, non-foundational):** the coding-agent-CLI runner adapter
  is implemented and wired but not exercised against a real LLM provider,
  because no provider credential (API key) and no coding-agent CLI exist on the
  Linode. The substrate is proven end-to-end with the deterministic adapter
  (which remains valuable for certification and isolation). Supply a provider
  credential (e.g., `DEEPSEEK_API_KEY`) + a CLI on the Linode to exercise the
  real-provider path; nothing else blocks.
- **Commit:** (see CP6 commit below)

## What changed
- `internal/agent` — the Agent substrate:
  - Role / Profile / Execution distinct; built-in roles (implementer,
    reviewer, conflict-resolver) with capabilities.
  - `CredentialStore`: AES-256-GCM encrypted-at-rest (key from
    `SWITCHYARD_SECRET_KEY` or a persisted data key); plaintext exists only in
    `ResolveForExecution` (scoped 0600 file); create/list-metadata/rotate/
    delete; the secret is never returned by any endpoint.
  - Runner interface + `DeterministicRunner` (Strut worker) and `CLIRunner`
    (wired, requires a CLI + credential).
  - `Execution` records (role, adapter, status, output, result).
- API: credentials create/list/rotate/delete; roles list; the run path now
  routes through the substrate (`role implementer -> execution -> edit -> ref
  commit`) and records `executions`.
- Trestle client: real `DeleteRecord` (If-Match) — required for credential
  deletion.

## Gate evidence
`experiments/cp6/cp6_gate.sh` (live): roles listed; credential created with the
secret absent from every response; list returns metadata only (no ciphertext);
rotate and delete succeed with no plaintext leakage; and a full
Work→Attempt→implementer-execution→edit→commit run completed with a recorded
`succeeded` execution and the change committed to the isolated branch.

## Security review
- Credentials encrypted at rest; no plaintext retrieval path; metadata-only
  API; resolution materializes a scoped 0600 file (delete-after-run by caller);
  rotate/delete tested. Provider secret does not grant Switchyard authority
  (capabilities are role-scoped).

## Impact on later checkpoints
- CP7 (durable workflows) can call `agent("implementer", …)` against the same
  substrate; the deterministic adapter keeps runs reproducible.
- CP8 (review/findings) uses the `reviewer` role.
- The bounded condition (real provider) should be resolved before CP7's real
  agent task, but the durable-workflow machinery itself does not depend on it.
